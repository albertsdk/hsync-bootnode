# Architectural decisions — hsync-bootnode

Log of design decisions taken during implementation. Each entry is
self-contained: it records how intent became code.

| # | Decision | Rationale | Where |
|---|---|---|---|
| 1 | UPnP implemented with **pure-stdlib SSDP + SOAP** (`urllib`, raw XML) instead of the originally considered `miniupnpc` library | No third-party binary dependency (multi-platform matrix stays clean: Linux armv7/RPi included), full control over the no-log invariant, the zero-touch loop is best-effort by design and must degrade to stateless without crashing | `python/src/hsync_bootnode/upnp.py` |
| 2 | `leave` removes **every `(cid, bucket)` record regardless of group** | The `leave` frame carries no `group` field and a CID identifies one peer uniquely; a grouped register must not survive its own leave | `python/src/hsync_bootnode/routing.py:117` |
| 3 | CLI is a **Typer multi-command app** (`run` subcommand + top-level `--version`, bare invocation prints help) | Leaves room for future subcommands; the single-command Typer shape could not even parse `run` | `python/src/hsync_bootnode/cli.py:36` |
| 4 | CID pattern `^[A-Za-z0-9]{21}$` is a **local mirror** of `hsync_common.models.event.CID_PATTERN` until the hsync-common SSOT migration | The Python v1 must not depend on a not-yet-existing `hsync-common` protocol module; the SSOT migration replaces the mirror with the SSOT import + drift test | `python/src/hsync_bootnode/protocol.py` (completed by #26) |
| 5 | TLS identity is **generated per process by default** (ephemeral, in-memory); an operator may opt into a **persistent** identity with `run --identity PATH` (see #29/#30) | No-log by construction in the default run: with no identity file there is no key/cert to protect and nothing is written to disk; a fresh fingerprint per restart is acceptable unless the operator pins it, and pinning requires the opt-in persistent identity | `python/src/hsync_bootnode/server.py:91` (`make_identity`, `load_or_create_identity`) |
| 6 | Rate limiting uses **in-memory sliding windows** keyed by IP/(IP,bucket)/bucket, not a persistent store | Spec §5; nothing may be written to disk, so limits restart with the process | `python/src/hsync_bootnode/ratelimit.py` |
| 7 | Build/packaging is split: **root entry point** (`compile.sh`, `native`/`rpi`/`deb`/`deb-all`, `-l/--language` default `python`, `rust` fail-fast until that port exists) + **per-language binary script** (`python/compile.sh`: `native`/`onedir` only, no packaging logic) | A script inside one implementation directory must not own another language's toolchain; the future port plugs into the dispatch points (`validate_language`, `_build_native`, `_build_onedir`, `_container_native_cmd`, `_container_build_cmd`) | `compile.sh`, `python/compile.sh`, `packaging/deb/` |
| 8 | PyInstaller excludes dev-only venv packages (`mypy`, `mypy_extensions`, `ruff`) | `--collect-submodules hsync_bootnode` follows the analysis import graph and drags dev packages installed in the same venv into the bundle; they are never imported at runtime (verified by probe build: binary runs, `mypy` gone) | `python/compile.sh:234` |
| 9 | `_read_frame` keeps a per-stream `pending` buffer so pipelined frames on one stream are each answered in order (previously the second frame in one TCP/QUIC read was lost) | One NDJSON stream must not drop frames the client legally pipelined; the fix is transport-only, no wire-contract change; covered by `test_loopback_pipelined_frames_on_one_stream` | `python/src/hsync_bootnode/server.py:378`, `python/tests/test_server.py` |
| 10 | **Opt-in debug mode** (`--debug` / `HSYNC_BOOTNODE_DEBUG=1`) emits diagnostics to stderr (frame types, outcomes, refusals, prune/lifecycle). *Superseded on the PII question by #25; the module is `diagnostics.py` since #36.* | The no-log invariant forbids logging peer data to disk; a silent-by-default, explicitly enabled stderr sink keeps diagnosis possible without weakening the invariant | `python/src/hsync_bootnode/diagnostics.py`, `cli.py` |
| 11 | **Readiness seam** (`--ready-file` / `HSYNC_BOOTNODE_READY_FILE`) writes the process PID once the QUIC listener is bound (removed on graceful shutdown); SIGTERM is routed to the graceful path | Tests/orchestrators need a deterministic readiness signal (mirrors the client's `HSYNC_READY_FILE`); the file carries no peer data, so it does not violate no-log | `python/src/hsync_bootnode/cli.py` |
| 12 | **`--ttl`** (default 60, 1–3600) makes the record TTL operator-configurable | The spec fixes TTL 60 s, but a configurable TTL is a legitimate operational knob and lets the BB TTL-convergence test run in seconds without waiting a full minute | `python/src/hsync_bootnode/cli.py` |
| 13 | **Black-box suite is language-neutral** and lives at the repo root (`tests/`), not under `python/` | The language-neutral suite: the same functional tests must validate `python/` and the future `rust/` implementation unchanged; they spawn the binary via `HSYNC_BOOTNODE_BIN` and speak only the public CLI + `boot/1` wire protocol, importing nothing from `hsync_bootnode` | `tests/`, `bench/` |
| 14 | **`--no-rate-limit`** / `HSYNC_BOOTNODE_NO_RATE_LIMIT=1` disables every token bucket (benchmark/test seam, never a production option) | The loopback benchmarks would otherwise measure `rate_limited` responses (the query/register bursts are 10/10); an explicit seam keeps L2/L3 numbers on the unthrottled fast path while the BB suite still covers rate-limit behaviour | `python/src/hsync_bootnode/handler.py`, `cli.py`, `bench/` |
| 15 | Black-box readiness keys on the ready file **appearing with a PID**, not on PID equality with the launcher; `wait_ready` stores that PID on `handle.node_pid` | A onefile-packaged binary (PyInstaller `--onefile`, the target shipped in the `.deb`) runs the app in a child process, so its `os.getpid()` differs from `subprocess.Popen.pid`; the previous equality check made the whole language-neutral suite and the L2/L3 benchmarks time out against the packaged binary. The ready path is unique per test, so the file appearing is unambiguous. `soak.py` reads RSS from `node_pid`, not the launcher | `tests/harness.py`, `bench/soak.py`, `tests/test_harness_readiness.py` |
| 16 | **Single-pass response serialization**: `BootHandler.handle` returns the already-serialized JSON string (`model_dump_json()`), so the transport writes it verbatim instead of `json.dumps(model_dump(), sort_keys=True)`. This also changes the wire key order from alphabetical to model field order, which **matches** `protocol-spec/boot-1.md` and `fixtures/bootnode-*.json` (a byte-level change, but no client parses order). `error`/`retry_after` stay present on success as `null` because the language-neutral suite reads `response["error"]`. Non-ASCII values are now emitted as raw UTF-8 instead of `\uXXXX` escapes (benign, byte-level only). | Eliminates the double pass over the response (pydantic dict + `json.dumps`) and aligns Python's wire order with the SSOT and the future Rust port. Locked by the golden wire test `test_wire_serialization_is_compact_and_spec_ordered` | `python/src/hsync_bootnode/handler.py`, `server.py`, `python/tests/test_handler.py` |
| 17 | **Materialized peer projection + secondary indexes + bounded rate-limit state**: `PeerRecord` carries a lazily-built `wire` (`BootPeer`) projection (a covering projection, valid for the record's lifetime); `RoutingTable` adds `_by_group`/`_by_cid`/`_pos` indexes so `sample`/`remove`/`count(bucket,group)` are O(bucket)/O(1) instead of O(n), and `prune` rebuilds the indexes in bulk when ≥ 50% of records expire; `TokenBucketLimiter.evict_stale` drops fully-refilled buckets (behaviour-identical, bounds memory) on the background sweep. | The routing scan was the hot-path bottleneck; indexes turn it into lookups, the projection removes per-query `BootPeer` construction, and the eviction stops unbounded dict growth under IP churn | `python/src/hsync_bootnode/routing.py`, `ratelimit.py`, `handler.py` |
| 18 | **Single-pass frame validation**: `handle(raw: bytes)` validates with the discriminated union `BootFrame` via `BOOT_FRAME_ADAPTER.validate_json`, replacing the transport's `json.loads` + `model_validate(dict)` two-pass path. Admission is charged **after** validation, so only *valid* frames consume a per-IP token: malformed/unknown frames stay silently dropped (spec) and can no longer drain a shared NAT IP's bucket (an earlier charge-before-validate variant caused that collateral throttling and was reverted — it also did not actually bound parse CPU, since validation ran regardless). | One Rust pass (parse + discriminate + validate) is faster than `json.loads` + dict dispatch + `model_validate`, and the validate-first ordering keeps both spec clauses ("malformed → silently dropped", "valid over-limit → explicit `rate_limited`") without collateral throttling | `python/src/hsync_bootnode/protocol.py:220`, `handler.py`, `server.py` |
| 19 | The L2 `quic-handshake` benchmark times **only** the handshake (`connect.__aenter__`); the context-manager teardown runs outside the timed region. New L4 `bench/profile_handshake.py` breaks the cost down | Profiling showed the old metric (~122-188 ms) was ~90% the `aioquic` closing drain: `close()` + `wait_closed()` blocks on `_close_at = now + 3 * PTO` (`aioquic/quic/connection.py`) with ~0.4% CPU, while the genuine handshake is ~16 ms (client CPU ~55%). The fix is a measurement correction — a faster implementation language cannot remove the drain timer. `client_config()` was extracted to `tests/harness.py` (3rd use: `BootClient` + both benchmarks) to share the QUIC client config | `bench/bench_quic.py`, `bench/profile_handshake.py`, `tests/harness.py`, `bench/README.md` |
| 20 | **Response bytes end-to-end + bounded sampler + truncate-on-full prune**: `handle()` returns serialized JSON as `bytes` via module-level `TypeAdapter`s (`BOOT_ACK_ADAPTER`/`BOOT_RESPONSE_ADAPTER`, `dump_json()`), so the transport writes `response + b"\n"` verbatim — no `.decode()` in Pydantic and no `.encode()` in `server.py`. `RoutingTable.sample` caps the rejection loop at `max(4k, 64)` distinct draws and falls back to one linear pass, bounding the stale-group worst case at O(n) instead of the coupon-collector O(n log n). `RoutingTable.prune` clears all four structures in one C-level pass when the whole table is expired (TRUNCATE-equivalent) instead of N deletes + a rebuild. | Each change removes avoidable work on a hot path: the decode/encode round-trip per reply, unbounded `randrange` draws when a group is mostly expired (could block the single event loop for ~100k draws at 10k stale entries), and per-record index teardown on mass expiry | `python/src/hsync_bootnode/protocol.py`, `handler.py`, `server.py`, `routing.py` |
| 21 | CPU is **measured, not assumed**: L5 `bench/cpu_saturation.py` sweeps concurrent query load and samples the *node* process CPU from `/proc/<pid>/stat` (utime+stime), reporting load → CPU% (of one core) → p50/p99; `soak.py` now logs CPU% next to RSS. Shared `/proc` helpers (`proc_cpu_seconds`, `proc_rss_mb`, `cpu_percent`, `format_cpu`) live in `bench/common.py`. | Deciding whether vertical scaling / parallelism / a Rust port is warranted needs evidence that one core saturates; the single-process asyncio loop cannot exceed ~100% of one core, so this table is the gate. No multithreading/pool (GIL-bound, micro-work units) and no `SO_REUSEPORT` multi-worker (state sharding breaks discovery, or the no-log invariant if externalized) | `bench/cpu_saturation.py`, `bench/common.py`, `bench/soak.py`, `bench/README.md` |
| 22 | **Node-wide private mode** (`--private` / `HSYNC_BOOTNODE_PRIVATE=1`): the protected-bucket policy widens from the operator's declared `--protected-bucket` set to *every* bucket, `leave` included. Implemented as one policy check in `_authorize` (`self._private or bucket in self._protected`) plus a keyed lookup `self._tokens.get(bucket)` so an unprovisioned bucket is refused like a wrong token — no bucket-existence/provisioned-set oracle, same uniform `token_required` and same failed-token budget. Startup with zero group keys raises `BootConfigError` (exit 2) from `BootHandler.__init__`, so the CLI needs no extra validation branch. `BootLeave` gained the optional `bucket_token` field the spec already documents; a gated refusal on `leave` is a silent drop because the spec defines no `leave` response frame | Authenticated bootstrap nodes are the industry norm for private meshes (derper `-verify-clients`, libp2p pnet, Nebula lighthouse), and the HMAC-capability model already existed in the protected-bucket model — the feature is a policy switch on an unchanged wire contract (no field, no `protocol_version` bump, no client mode). Keeping the refusal uniform preserves the anti-enumeration property the open mode already guarantees, and failing fast avoids serving a node that would refuse every frame | `python/src/hsync_bootnode/handler.py`, `protocol.py`, `cli.py`, `protocol-spec/boot-1.md` (§Auth), `python/tests/{test_handler,test_cli,test_server,test_nolog}.py`, `tests/test_bb_bootnode_private.py` |
| 23 | **`capacity` is the advisory service-capacity hint** (domain `0..32`, `0` = not a peer-download seeder; `CAPACITY_MAX` in `protocol.py`). The handler copies it from `register` onto `PeerRecord` and relays it in every `query` peer (`BootPeer.capacity`), in both the advertised-endpoint and observed-source branches. It is **not authenticated and not authoritative**: the requester may use it only to pre-size concurrency and to skip `capacity=0` peers, never to exclude a live seeder; the authoritative value stays `serve_slots` on the authenticated data-plane handshake (ADR 0030). The sample is never ordered by it (random, no self-promotion) and `refresh` neither carries nor mutates it | Makes the field meaningful without contradicting ADR 0030: a discovery-time hint is allowed as long as it never gates candidacy (the sample stays random and complete) and the authenticated handshake remains the authority. The domain is `0..32`, mirroring the authenticated `serve_slots`, enforced atomically across spec, models, fixtures and tests | `python/src/hsync_bootnode/{protocol,routing,handler}.py`, `protocol-spec/boot-1.md`, `fixtures/bootnode-response.json`, `python/tests/{test_scaffold,test_handler}.py`, `tests/{harness,test_bb_bootnode_query,test_bb_bootnode_negative}.py` |
| 24 | **`reachable` is derived from `bool(endpoints)`** at register time (previously hardcoded `true`): a peer is advertised as reachable only if its `register` carried at least one listen endpoint, i.e. it can act as a data-plane master. A register with no endpoint (the first STUN register, before the public TCP endpoint is known) is advertised with `reachable=false` and its observed UDP source as the fallback endpoint. `refresh` never changes `reachable`; a change requires a new `register` | The response must not present a slave-only peer (no published TCP endpoint) as a data-plane master: `_to_peer` already falls back to the observed UDP source, so the flag is what lets a requester tell a real master from a bootstrap-only entry. Deriving it at register keeps the value consistent with the advertised endpoint and immutable for the record's lifetime, so the materialized wire projection cannot go stale | `python/src/hsync_bootnode/{handler,routing}.py`, `protocol-spec/boot-1.md`, `python/tests/test_handler.py`, `tests/test_bb_bootnode_query.py` |
| 25 | **The debug mode is the full operation log, peer identity included** (`--debug` / `HSYNC_BOOTNODE_DEBUG=1`): `debug_event` follows the whole request life cycle — `session open/close`, `frame <type>`, `register ack`/`refused`/`rate_limited`, `refresh`, `leave`, `query response`, `prune`, `drop invalid-frame`/`oversized-frame` — with the CID, bucket, group, peer IP:port, endpoint count, capacity and connected count. It is stderr-only, opt-in, and never written to disk; without `--debug` nothing peer-related leaves memory (the default remains silent, and `tests/test_bb_bootnode_lifecycle.py` pins both the verbose log and the silent default). | An operator debugging reachability needs to know *who* connected and *what* the node decided; a summary without the identity is not actionable. The no-log invariant is about disk, not about an explicitly requested stderr stream, so the previous non-PII restriction was self-imposed rather than required — and it is now lifted *only* behind the opt-in flag, keeping the default run silent and in-memory | `python/src/hsync_bootnode/diagnostics.py`, `handler.py`, `server.py`, `cli.py`, `tests/test_bb_bootnode_lifecycle.py`, `python/tests/test_diagnostics.py`, man page, `docs/usage.md` |
| 26 | **SSOT sync**: `protocol.py` imports `CID_PATTERN` from `hsync_common.models.event` and validates every wire `bucket` with `hsync_common.path_validation.is_valid_bucket_name`, replacing the local CID mirror and the ad-hoc `min_length=1, max_length=128` bound. The Python v1 therefore reuses hsync-common generic utilities (TLS identity via `ssl_utils`, CID/bucket validators) while `protocol-spec/boot-1.md` + `fixtures/` stay the SSOT for every language. | The local mirror was always temporary (decision #4) and the dependency already existed (`hsync-common==1.0.0`; `ssl_utils` in `server.py`); the client mirror already enforced the canonical bucket rule, so a daemon that accepted a non-canonical bucket produced query responses the client could not parse. | 27 | **Listener bind failure is a dedicated exit code (3) with an actionable message**: `cli.run` wraps the `start_server` call in `_async_main` into a `ListenerBindError(host, port, errno)`, catches it around `asyncio.run` and prints a stderr message naming `host:port` and the cause before exiting with code 3. The errno is read from the `OSError` or its `__cause__` (`_errno_from`) because aioquic raises a bare `OSError` without an errno; the message branches on `EACCES`/`EPERM` (privileged port → `--port ≥ 1024` / root / `setcap cap_net_bind_service` / systemd unit), `EADDRINUSE` (port in use), `EADDRNOTAVAIL`/`EINVAL` (bad `--host`), and a fallback. Exit 2 remains the configuration error and 0 a clean stop. | A raw PyInstaller traceback on a bind failure told the operator nothing; a dedicated code lets systemd/scripts distinguish misconfiguration (2) from an unavailable port (3). The message keywords are part of the CLI contract, so the Rust port must reproduce them — enforced by `tests/test_bb_bootnode_lifecycle.py::test_port_in_use_fails_fast_with_actionable_error` (the EACCES path is white-box only, since root can bind 443) | `python/src/hsync_bootnode/cli.py` (`ListenerBindError`, `_errno_from`, `_bind_error_message`), `python/tests/test_cli.py`, `tests/test_bb_bootnode_lifecycle.py`, man page (`EXIT STATUS`), `docs/usage.md` |
| 28 | **The bootnode default port stays 443 and becomes a single SSOT**: the CLI `--port` default is `BOOT_DEFAULT_PORT` imported from `hsync_common.protocol.bootnode` (mirror of `boot-1.md` §Transport), so it can never drift from the client's default (`BOOTNODE_DEFAULT_PORT` re-exports the same constant). 443 is kept because it is the canonical QUIC/HTTP3 port and the most firewall/NAT-permissive path for a public rendezvous node; the privileged-bind concern is a deployment detail already handled by the systemd unit (`CAP_NET_BIND_SERVICE`), `setcap` and the exit-3 message. | The value was already 443 on both sides but duplicated in the bootnode CLI, the client constant and the spec/doc prose, so it could silently drift. | 29 | **Opt-in persistent identity + `sha256:<hex>` trust fingerprint (ADR-0034)**: the identity stays in-memory per process by default (no-log invariant intact); `run --identity PATH` persists an Ed25519 key+cert (`0600` file / `0700` dir) via `load_or_create_identity`, and `identity show`/`identity rotate` manage it. | 30 | **TLS identity key type is ECDSA P-256 (was Ed25519)**: `generate_ecdsa_private_key` (P-256) replaces `generate_ed25519_private_key` as the key used by `make_identity`, `load_or_create_identity` and `rotate_identity`; `_load_identity_file` also accepts EC keys. | 31 | **The election advertisement is relayed on `boot/1`** (`server_ready`, `force_master`, `never_master`, `startup_time`, `sync_direction`): `BootRegister` gains five optional fields (documented defaults: `false`, `false`, `false`, `0.0`, `bidirectional`) and every `query` peer echoes them verbatim, exactly like the advisory `capacity` hint | A bootnode-discovered peer must take part in the client's master election with the same inputs a mDNS-discovered one provides. | 35 | **Debug lines are timestamped and self-identifying**: every line is `2026-09-30T10:30:45.123Z - hsync-bootnode[1234] debug: <event> k=v ...` — timestamp from the `hsync-common` SSOT (`utc_now_iso()`, UTC, ISO-8601 `Z`), identity as `source[pid]` (`os.getpid()`, resolved per line), then the single `debug:` channel marker; both `debug_log` and `debug_event` render through one private `_emit` | The node's own deployment units discarded stderr when this was decided (`StandardError=null`, launchd `/dev/null`, WinSW `<log mode="none"/>`; #36 later routed stderr to the system log), so **no** log transport added a receipt time or a process identity to these lines: the operator's dumped stream is the whole artefact, and it must be orderable and correlatable with the timestamped `hsync-client`/`hsync-server` logs — without it there is no way to line up a client `register` with the node's decision or to tell two instances sharing one stderr apart.
